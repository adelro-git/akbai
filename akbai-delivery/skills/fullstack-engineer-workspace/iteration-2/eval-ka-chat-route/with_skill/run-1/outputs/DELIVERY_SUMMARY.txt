================================================================================
12-STEP FLOW (IN ROUTE.TS)
================================================================================

1. Auth Check
   └─ Verify session → get user ID
   └─ Returns 401 if unauthenticated

2. Request Validation
   └─ Parse JSON body
   └─ Validate with ChatRequestSchema (Zod)
   └─ Returns 400 if invalid

3. Load User Profile
   └─ Fetch user data from users table
   └─ Fetch business data from businesses table
   └─ Returns 404 if user not found

4. Tier Validation
   └─ Free tier: count messages sent today
   └─ Limit free tier to 10 messages/day
   └─ Returns 403 if limit reached

5. Build KA Prompt
   └─ Dynamic system prompt from context
   └─ User name, business, tier, today's date
   └─ KA voice rules + scope boundaries

6. Circuit Breaker Check
   └─ Query ai_spend_log for today's total spend (Manila time)
   └─ Compare against ₱500 daily cap
   └─ Returns 503 if cap exceeded

7. Model Selection
   └─ selectModel(task='ka_reasoning', tier=user.tier)
   └─ Free → Haiku, Pro/Business → Sonnet
   └─ Log model choice

8. Claude API Call
   └─ retryWithBackoff wrapper (max 3 retries, exponential backoff)
   └─ Send system prompt + user message
   └─ Returns 429/500+ errors (handled by retry logic)
   └─ Returns 500 if retries exhausted

9. Validate Response
   └─ Extract text from Claude response
   └─ Ensure non-empty
   └─ Returns 500 if empty (should never happen)

10. Calculate Cost & Record Spend
    └─ calculateCost(model, inputTokens, outputTokens)
    └─ Convert to PHP centavos
    └─ recordSpend(userId, costCentavos, model)
    └─ Insert into ai_spend_log

11. Store Conversation
    └─ Insert user message to ka_conversations
    └─ Insert KA response to ka_conversations
    └─ Include tokens, model, cost, scope
    └─ Non-blocking (doesn't fail request if storage fails)

12. Return Success Response
    └─ Standard envelope: { success: true, data }
    └─ ChatResponse = content + tokens + model + cost
    └─ Status 200

================================================================================
DATABASE TABLES REQUIRED
================================================================================

users
  id UUID PRIMARY KEY
  email TEXT UNIQUE
  first_name TEXT
  subscription_tier TEXT ('free', 'pro', 'business')
  business_id UUID REFERENCES businesses(id)
  created_at, updated_at, deleted_at TIMESTAMPTZ

businesses
  id UUID PRIMARY KEY
  user_id UUID REFERENCES users(id)
  name TEXT
  type TEXT (e.g., "home bakery", "sari-sari store")
  created_at, updated_at, deleted_at TIMESTAMPTZ

ka_conversations
  id UUID PRIMARY KEY DEFAULT gen_random_uuid()
  user_id UUID NOT NULL REFERENCES users(id)
  role TEXT ('user', 'assistant')
  content TEXT
  scope TEXT ('financial', 'birkto', 'communication', 'general')
  input_tokens INTEGER (null for user messages)
  output_tokens INTEGER (null for user messages)
  model TEXT (null for user messages)
  cost_centavos INTEGER (null for user messages)
  created_at, updated_at, deleted_at TIMESTAMPTZ

ai_spend_log
  id UUID PRIMARY KEY DEFAULT gen_random_uuid()
  user_id UUID NOT NULL REFERENCES users(id)
  cost_centavos INTEGER
  model TEXT
  created_at TIMESTAMPTZ

All tables have RLS policies (see IMPLEMENTATION.md for SQL)
