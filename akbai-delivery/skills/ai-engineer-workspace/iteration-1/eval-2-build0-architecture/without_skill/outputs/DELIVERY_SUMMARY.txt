WHAT'S INCLUDED
---------------

1. SYSTEM PROMPT ASSEMBLY ARCHITECTURE
   - 5-layer assembly design (Core Persona → Active Domains → User Context → Conversation History → Feature Context)
   - Server-side only (never exposed to client)
   - Complete pseudocode implementation in TypeScript
   - Architecture diagram and step-by-step flow

2. CORE KA PERSONA BLOCK (~800 tokens)
   - Identity, voice pillars, communication rules
   - Tone calibration by context (morning briefing, tax deadline, error, etc.)
   - Universal boundaries (no tax advice, no guaranteed outcomes, warm + competent)
   - Error recovery pattern (acknowledge → take responsibility → explain → next step)

3. MODULAR DOMAIN SCOPES (Phase 1)
   - [FINANCIAL_SCOPE] — income, expenses, profitability, cash flow
   - [TAX_SCOPE] — BIR deadlines, filing reminders, compliance
   - [COMMUNICATION_SCOPE] — customer DM drafting, warm tone
   - Each scope includes: role, in-scope queries, out-of-scope redirects, disclaimers, boundaries

4. PHASE 4+ DOMAIN EXPANSION PROTOCOL
   - Template for adding new domains (Marketing, Strategy, HR, Inventory)
   - Feature flag system for gradual rollout
   - Conversation domain tagging (prevents context bleed)
   - Redirect logging for demand signal tracking
   - Zero code rewrites — pure configuration changes

5. BIR DISCLAIMER RULES (Hard-Coded, Non-Negotiable)
   - Taglish + English versions
   - Every tax response includes: "Paalala: Ang guidance na ito ay informational lang. I-verify mo sa iyong accountant o CPA bago mag-file."
   - Persistent in-app disclaimer visible in chat UI
   - Clear escalation patterns for when to defer to professionals

6. PROMPT INJECTION DEFENSES (All 5 Attack Vectors)
   - System prompt leak attempts
   - Role confusion / jailbreak attacks
   - Context injection / impersonation
   - Tax/legal strategy override attempts
   - User impersonation via token spoofing
   
   Defense mechanisms:
   - Output validation pipeline (8 checks before response returned)
   - Security logging to Sentry
   - Graceful error responses (never expose system details)

7. CONVERSATION HISTORY MANAGEMENT
   - Domain-tagged conversations table structure
   - RLS policies (users read/write own data only)
   - Soft delete + 30-day retention window
   - Domain isolation (financial history doesn't see tax history)

8. PRODUCTION DEPLOYMENT CHECKLIST
   - 11 pre-deployment gates (all critical)
   - 3-phase rollout strategy (10% → 50% → 100%)
   - Monitoring dashboards (validation metrics, disclaimer compliance, domain adoption, performance)

9. TESTING & REGRESSION FRAMEWORK
   - 20–30 test cases covering all domains
   - Test library structure (tax-scope.test.ts, injection-defenses.test.ts, taglish-style.test.ts, etc.)
   - Example tests included (disclaimer compliance, prompt injection, Taglish consistency)
   - Test coverage targets (90–100% depending on category)

10. APPENDICES
    - Appendix A: Complete realistic system prompt assembly example (Maria, Pro tier, financial query)
    - Appendix B: Full Phase 4 [MARKETING_SCOPE] example (ready to copy-paste)
