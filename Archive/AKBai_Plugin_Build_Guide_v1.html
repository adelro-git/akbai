How to Use This Guide
Each skill section gives you everything needed for a single build session: the SKILL.md content spec, reference file outlines, and the exact prompt to paste into a fresh Claude conversation.

The Build Process for Each Skill

For every skill in this guide, you follow the same 5-step process:

  1. Open a fresh Claude conversation — one skill per session, never stack skills.
  2. Invoke the skill-creator skill — say "use skill-creator" to load the creation workflow.
  3. Paste the build prompt from this guide — each skill section has a pre-written prompt with all the context Claude needs.
  4. Review the draft SKILL.md — Claude will generate the skill file. Review it, request changes, iterate.
  5. Write reference files — Claude will also draft the reference docs. Save everything to the plugin directory.
Critical: Build Shared Context First

Before building any skill, you must create the shared/ reference files (Section 02). Every skill reads from shared/project-context.md — if it doesn't exist, your skills will hallucinate context instead of referencing real data.

fullstack-engineer

Phase A

The workhorse skill. Writes Next.js components, Supabase queries, API routes, and Edge Functions. Knows AKBai's code conventions and follows established patterns.

SKILL.md Content Spec (~300 lines)

  • Role Definition — "You are a senior fullstack engineer building AKBai. You write production-quality TypeScript. You follow the established patterns in the codebase. You ask for the ADR if a design decision isn't clear rather than guessing."
  • Code Generation Protocol — (1) Check if an ADR exists for this feature, (2) review the Supabase schema for relevant tables, (3) scaffold: page route → component → API route → Supabase query → types, (4) always include error handling and loading states, (5) all user-facing text in Taglish.
  • Component Patterns — Card component structure (AKBai uses a Chat + Card hybrid UI). Mobile-first responsive. Tailwind CSS only. Feature folders: /app/(features)/resibo/, /app/(features)/deadline/, etc.
  • Supabase Patterns — Always use typed client. RLS policies on every new table. Soft-delete pattern (deleted_at timestamp, not hard delete). Edge Functions for webhooks only. Service role key NEVER in client code.
  • Claude API Patterns — All Claude calls server-side via API route. Structured JSON response with Zod validation. Haiku for classification/OCR, Sonnet for generation/reasoning. Daily spend cap circuit breaker. Retry with exponential backoff (max 3 retries).
  • Error Handling — Every API route returns {success, data, error} shape. Client-side error boundaries on every feature page. Taglish error messages for users, English for logs.

data-architect

Phase A

Owns the Supabase schema, RLS policies, data migrations, and NPC-compliant data flows. Schema decisions happen early and are hard to change — this skill ensures they're right from Day 1.

SKILL.md Content Spec (~250 lines)

  • Role Definition — "You are the data architect for AKBai. Every schema decision must be NPC-compliant (RA 10173), support RLS isolation, and be migration-safe. You think about data flows across the full lifecycle: collection → storage → processing → deletion."
  • Schema Design Protocol — (1) Define the table purpose and relationships, (2) add RLS policy (always user_id based), (3) add soft-delete column (deleted_at), (4) add audit columns (created_at, updated_at), (5) generate migration SQL, (6) document in schema reference.
  • Core Tables — users, businesses, transactions, receipts, invoices, bir_deadlines, ka_conversations, subscriptions. Each with RLS, soft-delete, audit columns.
  • NPC Data Flow Compliance — Data classification (PII vs business data vs analytics). Encryption at rest (Supabase default). Data retention schedule (user can request deletion, 7-day purge window). Audit log for data access.
  • Migration Strategy — Always create migration SQL files. Never alter production schema without a migration. Use Supabase CLI for migration management. Rollback plan for every migration.

Slash Command Specs
Each command is a single Markdown file in commands/ that invokes the right skill(s) and follows a defined protocol. Build these alongside or after their parent skills.
Command Primary Skill What the .md File Should Contain
/sprint project-manager Instructions to: (1) read current phase from project-context.md, (2) check gap-registry.md, (3) generate sprint plan with 3–5 tasks sized for 10–15 hrs, (4) output in sprint plan template format.
/build [feature] solutions-architect → fullstack-engineer Chain: (1) check for existing ADR, (2) design schema changes via data-architect patterns, (3) scaffold feature folder structure, (4) generate implementation with tests. Output: working code + migration SQL.
/review fullstack-engineer + security-compliance Dual review: (1) code quality (conventions, error handling, types), (2) security (RLS, input validation, secrets exposure, prompt injection). Output: review comments with severity.
/test [scope] qa-engineer Generate test suite for specified feature. Use test-checklist.md for required scenarios. Output: Jest/Playwright test files ready to run.
/deploy devops-engineer Pre-deployment checklist: tests pass, env vars verified, migrations applied, Sentry release tagged, rollback plan. Output: Go/No-Go with blockers if any.
/incident devops-engineer + ops-lead Emergency protocol: (1) assess severity (P0/P1/P2), (2) immediate mitigation steps, (3) communication template for users, (4) if P0 data breach → NPC 72-hour notification checklist.
/standup project-manager Generate weekly standup from provided inputs: what shipped, what's next, blockers, metrics. Output: GitHub issue comment + build-in-public social post.
/gap-check project-manager + product-owner Read gap-registry.md, flag overdue items by severity, suggest top 3 priorities for current sprint. Output: gap status table + recommendations.
/sense-check product-owner + ops-lead Run 8-signal Sense Check Gate with provided metrics. Output: signal-by-signal Green/Yellow/Red assessment + Go/No-Go recommendation for Phase 1→2.
/schema [action] data-architect View, modify, or validate Supabase schema. Actions: "view [table]", "add [table]", "migrate [change]", "validate". Always output migration SQL.
/prompt [feature] ai-engineer Create or iterate on Claude API prompts. Load prompt-library.md, show current version, accept modifications, validate output format with Zod schema.
/copy [context] ux-designer Write Taglish UI copy for specified context. Load taglish-copy-guide.md. Output: copy variants (2–3 options), character counts, tone notes.
/compliance [type] security-compliance NPC compliance check, BIR legal review, or security audit. Load relevant checklist. Output: status of each item + action items for non-compliant items.
/metrics ops-lead Review business metrics from provided data. Output: MRR dashboard summary, trend analysis, single highest-leverage recommendation.
/retro project-manager Sprint retrospective: what worked, what didn't, what to change. Output: structured retro with action items for next sprint.
Building Commands

Each command is a single .md file in commands/. The file content is the instruction set Claude follows when the slash command is invoked. Keep each under 100 lines. The command should reference the parent skill's reference files by path, not duplicate their content. Build commands alongside their parent skills — when building project-manager, also create /sprint, /standup, /gap-check, and /retro at the same time.

One fresh conversation per session. Never try to build 2+ skills in one conversation — token overflow kills quality.   3. Test every command — Session 9 is dedicated to running each slash command and fixing issues.
  4. Optimize descriptions — Session 10 uses the skill-creator's description optimization loop to ensure triggers fire accurately.
