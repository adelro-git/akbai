⚠ 11 Additional Operational Gaps Identified in This Review

CRITICALOTP deliverability to Yahoo Mail PH — common among target users. Needs custom SMTP with warmed-up domain (not Supabase default SendGrid).
CRITICALWebhook idempotency for PayMongo — same payment webhook can fire twice on retry. Handler must deduplicate by payment_id before processing.
CRITICALOR number generation legality — BIR requires sequentially numbered Official Receipts from a registered OR series. Auto-generating receipt numbers needs legal sign-off before Automated Self-Invoicing ships.
IMPORTANTDependency monitoring — Anthropic API, Supabase, PayMongo, Google Cloud Vision each need health checks + graceful in-app fallback messages. No uptime monitoring tool defined (UptimeRobot or Better Uptime).
IMPORTANTData backup strategy — Supabase point-in-time recovery needs explicit enablement on the paid plan + a tested restore procedure.
IMPORTANTSession expiry UX — graceful Taglish re-auth prompt when session expires mid-use, not a raw error state.
IMPORTANTIncident response runbook — what happens at 2AM on a BIR deadline day when the app goes down? Solo founder needs a written protocol even if it's just: detect → post status → rollback → fix.
IMPORTANTBeta-to-paid transition — Phase 0C pilot users paying ₱99–₱199 need a defined migration path when Phase 1 launches at ₱299. Loyalty rate? Auto-upgrade? No mention in roadmap.
IMPORTANTPWA installation UX — no App Store listing means "Add to Home Screen" is non-obvious. Landing page and onboarding need an explicit install guide step.
PLANAdmin observability — Anton needs a way to see: active users, MRR, feature usage breakdown, Flag-as-Wrong queue. Even a Supabase dashboard + simple Retool view would suffice for MVP.
PLANData retention policy — NPC requires a defined retention period for churned users. Must be stated in Privacy Policy and enforced in the system (e.g., delete transactions after 1 year of inactivity).
